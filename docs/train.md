# Как устроен тренажёр

Тренажёр открывается из отчёта по одной слабой теме. Он не начинает новую диагностику и не меняет остальные баллы.

Кнопка «Отработать» есть у темы с баллом 0 или 1. Запрос — `POST /api/chat` с `action=practice` и кодом компетенции. Сценарий в `web/ChatService.java`, задания и разбор — в `llm/PracticeCoach.java`.

## Задание

У каждой компетенции есть готовый кейс и блок «В ответе нужно» из двух или трёх пунктов. Вводная фраза говорит, что тема закроется, когда названы все эти пункты. Названия инструментов и чужие процессы не требуются.

Текст кейса хранится в сессии. Следующая попытка проверяется уже по нему, а не по стартовой формулировке.

## Что считается максимумом

Тема закрывается только на 3 из 3.

Ответ, в котором своими словами назван каждый пункт задания, получает 3 сразу. Отрицание рядом со словом пункта не считается. Такой ответ не уходит на дополнительный спор с моделью.

Если пункты названы не все, попытку разбирает GigaChat. Ему сказано смотреть только блок «В ответе нужно» и не требовать готовый текст user story, список критериев, Jira, Confluence, Slack, согласование и прозрачность для стейкхолдеров. Без ключа тот же разбор собирает локальная рубрика.

Разбор ниже тройки состоит из трёх частей:

- почему не максимум — какой пункт задания не назван;
- какие приёмы нужны — как назвать именно его, без примера готового ответа;
- похожее задание — другой короткий кейс с тем же списком пунктов.

Если модель уходит в инструменты, «дополните прошлый ответ» или тему вне списка, этот кусок заменяется. Похожее задание тогда берётся из второго заранее написанного кейса той же компетенции. Пробел и балл в отчёте не меняются, фаза остаётся `practice`.

## Закрытие пробела

На тройке балл темы становится 3. Отчёт собирается заново: уровень, сильные стороны, пробелы, план и курсы пересчитываются уже без этого пробела. Карточка уходит с анимацией, карточка уровня коротко подсвечивается.

Слабый ответ вроде «не знаю» пробел не закрывает.
